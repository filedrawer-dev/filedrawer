# Migrations an older binary can't simply ignore, and whether each breaks a rollback
# (CODING_STANDARDS.md, SQL). One line each: <version> safe|breaks <why>.
# tests/it/migration_rollback.rs refuses a migration after 0031 that adds anything
# but tables, non-unique indexes and nullable or defaulted columns without one, and
# ops/deploy-production refuses to roll production back across a `breaks` line.
# A migration's own text is sqlx's checksum, so its line goes here, never in the file.
0033 breaks it drops entries.embargo_until and series.public_at, which an older binary reads and writes, and deletes embargoed and waiting entries and unread hidden series
0037 safe an older binary reads attachment_files.repo_url, which sets stored from 0037 on leave NULL, so it lists their files without the repo URL; the sets it stores itself count no origins toward the storage cap
0038 safe it adds a view, github_handles, and tables an older binary doesn't read; an older binary's account deletion leaves the link row, which the view hides and the tidy deletes
0039 breaks it rebuilds outgoing_mail to widen the CHECK on kind: an older binary reads a `change` or `change_notice` row as a notice with no text, which it deletes unsent, or sends as an empty email when the account is an admin's, so a change of address asked for before the rollback never gets its link; and its account deletion leaves the address in the account's email_changes row, which only a newer binary's tidy deletes
